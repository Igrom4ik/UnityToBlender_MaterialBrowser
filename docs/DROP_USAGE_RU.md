# Unity Material Drop — как пользоваться

Перетащили `.mat` на объект — получили готовый материал. Никакой предварительной
сборки библиотеки, никаких настроек папок.

## Установка

Для Windows x64 и Blender 5.2 скачайте из [Releases](https://github.com/Igrom4ik/UnityToBlender_MaterialBrowser/releases) оба архива: `unity_material_drop-0.5.3-windows-x64.zip` и `unity_material_browser-0.13.3-windows-x64.zip`. Установите оба через `Edit > Preferences > Get Extensions > Install from Disk` и полностью перезапустите Blender. Дополнения используют одинаковую версию скомпилированного ядра.

При отсутствии карты нормалей `Custom/Diffuse Bump Spec` материал создаётся с плоской нормалью и предупреждением. Для исходного рельефа необходимо разрешить указанную Unity-ссылку по GUID.

## Первое перетаскивание

1. Найдите `.mat` в **проводнике Windows**. Быстрый путь: в окне Project в Unity
   правой кнопкой по материалу → `Show in Explorer`.
2. Перетащите файл в 3D-вид Blender и отпустите **над объектом**.
3. Материал собирается и назначается объекту под курсором.

Первый материал из нового проекта может занять до минуты: если нужных GUID нет в
кэше и рядом с материалом, аддон индексирует проект. Индексация идёт в фоне —
вьюпорт продолжает работать, прогресс виден на панели `Unity Drop`, `Esc`
отменяет. Дальше всё мгновенно: индекс лежит в кэше и переиспользуется.

Можно проиндексировать заранее: панель `Unity Drop` → `Индексировать проект`.

## Из окна Unity перетащить нельзя

Unity не отдаёт файлы наружу — перетаскивание из окна Project работает только
внутри самой Unity. Поэтому есть два рабочих пути:

- **Проводник.** `Show in Explorer` в Unity, дальше обычное перетаскивание.
- **Буфер обмена.** Скопируйте полный путь к `.mat` и нажмите
  `Собрать по пути из буфера` на панели `Unity Drop`.

## Куда попадает материал

Режим объекта — весь объект. Режим редактирования — выделенные полигоны. Точнее
целиться не нужно: если материал нужен на часть модели, зайдите в режим
редактирования и выделите грани.

Настройка `Перетаскивание` меняет поведение в объектном режиме (панель
`Unity Drop` и настройки аддона):

| Режим | Что делает |
| --- | --- |
| `Весь объект` | заменяет материал во всех слотах объекта под курсором — по умолчанию |
| `Слот под курсором` | заменяет материал только той грани, на которую вы отпустили файл — как штатное перетаскивание материала в Blender |
| `Новый слот` | добавляет отдельный слот, существующие не трогает |
| `Только создать` | собирает материал в файле и никуда не назначает |

`И на выделенные объекты` применяет то же назначение ко всем выделенным
объектам. Если вы отпустили файл мимо геометрии, материал уходит активному
объекту: смысл перетаскивания всё равно был в том, чтобы получить материал на
том, с чем вы работаете. Куда он в итоге попал, видно в отчёте.

Несколько `.mat` можно перетащить сразу: первый ложится по выбранному режиму,
остальные добавляются слотами — иначе каждый следующий затирал бы предыдущий.

## Режим редактирования: на выделенные полигоны

Если меш открыт в режиме редактирования, перетаскивание назначает материал
**выделенным полигонам** — курсор и режим назначения при этом не участвуют:
выделение и есть заявленное намерение. Материал получает свой слот (существующие
не трогаются), и `material_index` меняется только у выделенных граней. Работает и
в многообъектном редактировании — по всем мешам, открытым в режиме сразу.

Полигоны не выделены — материал просто добавляется слотом, и об этом появляется
строка в отчёте. Несколько `.mat` за раз: на полигоны уходит первый, остальные
добавляются слотами.

Выключается настройкой `Режим редактирования: выделенные полигоны` — тогда
перетаскивание в режиме редактирования ведёт себя как в объектном.

Перетаскивание работает не только в 3D-виде: редактор шейдеров, панель свойств и
аутлайнер тоже принимают файл — там материал уходит на активный объект.

## Защита от дублирования

Один и тот же материал Unity не появляется в файле дважды. При каждом
перетаскивании аддон ищет, нет ли его уже в сцене, и берёт найденный:

1. **По GUID материала Unity** — главный признак. Файл `.mat` можно переименовать
   или перенести внутри проекта, GUID у него останется прежним.
2. **По пути в проекте** — если `.meta` прочитать не удалось.
3. **По абсолютному пути к `.mat`** — последний запасной вариант.

Учитываются и материалы, собранные соседним аддоном `unity_material_browser`
(его ключи `ump_*`): для художника это тот же материал, кем бы он ни был создан,
и второй копии появляться не должно. Такой материал переиспользуется, но
**не переписывается** — как и материал, слинкованный из библиотеки.

Если подходящих копий несколько, берётся та, которой реально пользуется файл:
сначала по числу пользователей, затем по короткому имени — то есть `Материал`, а
не `Материал.001`.

В отчёте видно, что именно произошло: `создан`, `переиспользован, уже был в
файле` или `пересобран, Unity изменился`.

### Если дубликаты уже есть

Кнопка `Объединить дубликаты` на панели `Unity Drop` собирает материалы,
пришедшие из одного `.mat`, в один: все объекты переводятся на оставшийся,
лишние удаляются, а суффикс `.001` с уцелевшего снимается. Действие отменяется
через `Ctrl+Z`.

### Если материал изменился в Unity

Перетащили тот же материал, а `.mat` с тех пор изменился — аддон **сначала
назначает** материал таким, какой он есть в файле, и только потом спрашивает,
пересобирать ли его из Unity. Порядок именно такой, чтобы отмена ничего не
стоила: перетаскивание уже сделало то, о чём его просили, а ваши правки в узлах
целы. В диалоге есть флажок `Запомнить ответ`.

Настройка `Материал изменился в Unity`:

| Значение | Что делает |
| --- | --- |
| `Спрашивать` | назначить как есть и спросить про пересборку — по умолчанию |
| `Обновлять` | пересобирать из Unity без вопросов |
| `Оставлять` | никогда не пересобирать: материал в файле важнее |

### Настройки

- `Переиспользовать материал` — выключите, если наоборот нужны независимые копии
  на каждое перетаскивание.

Кнопки `Перечитать из Unity` (панель материала в свойствах) и
`Перечитать все материалы` (панель `Unity Drop`) пересобирают вручную, без
вопросов: там это и есть явная просьба обновить.

## Панель материала

В свойствах материала появляется секция `Unity source`: путь в Unity, имя
шейдера, профиль конвертации и то, чего не хватило, — ненайденные текстуры и
несопоставленные свойства. Оттуда же — `Перечитать из Unity` и кнопка открытия
папки с исходным `.mat`.

## Параметры Unity

Свойства, которым нет соответствия в Principled — `_ZOffsetCameraDistance`,
`_SSSMultiplier`, игровые маски и переключатели, — не пропадают: они остаются на
материале и видны в свойствах материала → `Unity source` → `Параметры Unity`.
Тусклые строки — значения по умолчанию из шейдера, яркие выставлены в самом
материале. Так не нужно возвращаться в Unity, чтобы посмотреть, что там стояло.

## Отчёт

Панель `Unity Drop > Отчёт` показывает результат последнего перетаскивания:
сколько карт подключено, куда назначен материал и что пошло не так.

| Строка | Что значит |
| --- | --- |
| `шейдер не найден` | `.shader` не нашёлся; материал собран по данным одного `.mat` |
| `текстуры не найдены по GUID` | файл текстуры отсутствует в проекте или папка не проиндексирована |
| `Blender не читает файл` | формат текстуры Blender не поддерживает — чаще всего `.psd` |
| `не сопоставлены свойства` | свойство шейдера, которому нет соответствия в Principled; на вид материала это не влияет |

## Настройки

| Настройка | Смысл |
| --- | --- |
| `Режим редактирования: выделенные полигоны` | перетаскивание на меш в режиме редактирования назначает материал выделенным граням, а не всему объекту |
| `Материал изменился в Unity` | спрашивать перед пересборкой, обновлять всегда или никогда не трогать материал в файле |
| `Индексировать автоматически` | недостающие ссылки запускают индексацию проекта. Выключите, если предпочитаете индексировать вручную |
| `Поиск рядом` | сколько секунд перетаскивание ищет недостающее в папках вокруг материала, прежде чем перейти к индексации |
| `Индексировать Packages` | локальные пакеты проекта тоже содержат шейдеры и текстуры |
| `Индексировать PackageCache` | нужно материалам с шейдером из скачанного пакета (URP, HDRP); заметно замедляет индексацию |
| `Потоков чтения` | индексация ждёт диск, а не процессор, поэтому потоки помогают до определённого предела |
| `Кэш индекса` | где лежат индексы проектов. Пусто — папка данных расширения Blender |
| `Всегда применять цветовой тинт` | умножать базовую текстуру на цвет материала даже без доказательства со стороны шейдера |
| `Профили шейдеров` | свой JSON с правилами конвертации; матчится раньше поставляемых |
| `Язык` | язык интерфейса самого аддона, отдельно от языка Blender |

## Каналы и упаковка текстур

То же, что в `unity_material_browser`, — конвертер общий:

| Постфикс | Каналы | Куда идёт |
| --- | --- | --- |
| `_BC` | RGB base color | Base Color |
| `_BCA` | RGB base color, A прозрачность | Base Color + Alpha |
| `_BCH` | RGB base color, A высота | Base Color; альфа не идёт в прозрачность |
| `_NMG` | RG нормаль, B metallic, A gloss | распаковка: Metallic, Roughness и Normal |
| `_N` | нормаль | Normal Map |
| `_AO` | окклюзия | микс в Base Color |

Unity хранит smoothness, Blender — roughness, поэтому значение всегда
инвертируется: `roughness = 1 − smoothness`.

## Если что-то не так

**Файл не перетаскивается.** Расширение должно быть именно `.mat`. Отпускайте
над 3D-видом, редактором шейдеров, свойствами или аутлайнером.

**Материал пустой, в отчёте «текстуры не найдены по GUID».** Нажмите
`Индексировать проект`. Если не помогло — текстуры действительно нет в проекте
либо она лежит в `Library/PackageCache`: включите соответствующую настройку.

**Материал создался, но не назначился.** Ни под курсором, ни в активных
объектах ничего не было. Выделите объект и повторите либо перетащите прямо на
геометрию. В режиме редактирования — выделите полигоны.

**Проект переехал на другой диск.** Кэш индекса привязан к пути `Assets`; для
нового пути он построится заново при первом перетаскивании.
