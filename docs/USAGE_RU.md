# Unity Material Browser — как пользоваться

Аддон собирает из материалов Unity постоянную библиотеку ассетов Blender:
материалы появляются в Asset Browser каталогами по структуре папок Unity,
назначаются перетаскиванием и обновляются, когда в Unity что-то изменилось.

**Проект Unity только читается.** Ни одного файла внутри `Assets/` аддон не
создаёт и не меняет — ни `.meta`, ни служебных маркеров, ни скриптов на стороне
Unity.

---

## Что нужно

| | |
| --- | --- |
| Blender | 4.2 или новее (разрабатывается и проверяется на 5.2) |
| Проект Unity | доступен на чтение; закрывать Unity не обязательно |
| Папка под библиотеку | **вне** проекта Unity и вне git-репозитория |

Библиотека — производный артефакт: её можно удалить и собрать заново из Unity в
любой момент.

## Установка

Возьмите `unity_material_browser-<версия>.zip` со страницы Releases или соберите
сами:

```bash
python tools/build_extension.py --output-dir dist
```

В Blender: `Edit > Preferences > Extensions > Install from Disk`, выберите zip.
Панель аддона — в 3D-виде: клавиша `N`, вкладка `Unity Materials`.

## Первая сборка библиотеки

### Шаг 1. Папки Unity

Аддон читает **только те папки, которые вы добавили сами** — ни `Assets/`
целиком, ни проект не обходятся никогда. Это правило, а не оптимизация: ссылка
на файл вне выбранных папок останется неразрешённой и попадёт в отчёт.

Добавьте два типа источников:

- **Материалы** — папки, где лежат `.mat`. Подпапки сканируются автоматически.
- **Текстуры и шейдеры** — папки, из которых разрешаются ссылки по GUID.

Текстуры и шейдеры в Unity обычно лежат не рядом с материалами, поэтому их папки
нужно добавить отдельно. Пример для проекта `madout2`:

| Тип | Папка |
| --- | --- |
| Материалы | `Assets\ART\Environment\Textures\Blends` |
| Текстуры и шейдеры | `Assets\ART\Environment\Textures` |
| Текстуры и шейдеры | `Assets\ART\Environment\Materials_Tiles\Shaders` |

**Папку шейдеров пропускать нельзя.** Без неё материал уходит в режим
`material_only`: имя шейдера неизвестно, свойства не проверены по его
`Properties`, цветовой оттенок не применяется, лишние слоты не отбрасываются.
Разница видна сразу — материалы получаются серыми.

Кнопка `Ctrl`-клик в диалоге выбора добавляет несколько папок за раз, галочка
«Каждую подпапку отдельно» заводит по записи на каждую вложенную папку.

### Шаг 2. Папка библиотеки

Укажите пустую папку вне проекта Unity — аддон откажется писать внутрь `Assets/`.
В неё же автоматически кладётся `.gitignore`: библиотека в git не нужна.

### Шаг 3. Сборка

`Извлечь из Unity` — читает `.mat`, `.meta` и шейдеры, пишет по одному JSON на
материал. `Собрать библиотеку` — делает из JSON файлы `.blend`, каталоги и
превью. Обе фазы показывают прогресс, `Esc` отменяет.

JSON — источник истины, `.blend` — производное. Поэтому пересборка после правки
правил конвертации не требует доступа к Unity вообще.

### Шаг 4. Регистрация в Asset Browser

`Зарегистрировать в Asset Browser` добавляет папку в
`Preferences > File Paths > Asset Libraries` и выставляет способ импорта из
настроек аддона. Если библиотека уже была добавлена руками — эта же кнопка
починит у неё способ импорта.

## Работа с материалами

### Перетаскивание

Откройте Asset Browser, выберите каталог слева, перетащите материал на объект.

По умолчанию материал приходит **копией в файл**: его можно править, а `Ctrl+Z`
отменяет перетаскивание полностью. Обновление из библиотеки для таких материалов
— явная кнопка `Обновить материалы в этом файле`.

Альтернатива в настройках — **`Связь с библиотекой`**: пересборка библиотеки
доходит до всех сцен сама, но параметры материала становятся серыми, а `Ctrl+Z`
после перетаскивания оставляет связь в файле (так устроен undo в Blender:
подгруженные библиотечные данные он не выгружает).

### Пай-меню: `Ctrl+Shift+M`

В 3D-виде открывает меню активного материала:

| Сектор | Что делает |
| --- | --- |
| Параметры материала | базовый цвет, металличность, шероховатость, тинт, тайлинг, нормаль |
| Создать редактируемую копию | копия с новым именем, назначается выделенным объектам |
| Сбросить из Unity | пересобирает материал из библиотеки, отменяя ваши правки |
| Открыть Asset Browser | переключает область на браузер ассетов |

Хоткей можно переназначить в `Preferences > Keymap` — он зарегистрирован в
конфигурации аддона и не трогает раскладку Blender.

### Редактируемая копия

Оператор просит новое имя и отклоняет занятое, а также имя оригинала — **до**
того, как что-то создаст. Новое имя обязательно по одной причине: `Igrom
MaterialRemapper` при экспорте FBX сопоставляет материалы по имени, и копия с
именем оригинала переиспользовала бы исходный `.mat`, а ваши правки просто
потерялись бы.

Копия сразу назначается выделенным объектам и становится активным материалом,
поэтому панели «Adjust Last Operation» у этого оператора нет: повторный запуск
попал бы на только что созданную копию. Чтобы сделать ещё одну, вызовите оператор
заново — имя предложится следующее свободное (`..._edit`, `..._edit_02`).

Копия — обычный материал Blender: ноды, текстуры, шейдер правятся без
ограничений. Пути текстур сохраняются как есть и ведут в `Assets/` — ни один
пиксель никуда не копируется. С копии снимается `ump_unity_guid` и пишется
происхождение (`ump_derived_from`, `ump_derived_name`, `ump_derived_hash`),
поэтому обновления библиотеки её не трогают.

## Обновление из Unity

`Проверить обновления` показывает `новых N / изменённых M / пропавших K`.
Изменением считается:

- правка `.mat`;
- замена текстуры (сверяются размер и время файла, а не содержимое);
- правка `.shader` — он решает значения по умолчанию и то, какие свойства живые;
- поднятая версия парсера аддона — улучшенный разбор читает те же файлы иначе.

`Собрать только изменённые` перестраивает затронутое. Материалы, пропавшие из
Unity, остаются в библиотеке и никогда не удаляются молча.

## Настройки

| Настройка | Смысл |
| --- | --- |
| Перетащенный материал | `Копия в файле` (правится, откатывается по `Ctrl+Z`) или `Связь с библиотекой` (только чтение, обновляется сама) |
| Упаковка | `Один файл на папку` — меньше файлов и быстрое сканирование; `Один файл на материал` — пересборка трогает один маленький файл |
| Создавать превью | рендер иконок в отдельной сцене; PNG лежит рядом с материалом и переиспользуется |
| Применять цветовой тинт всегда | умножать цвет на базовую текстуру даже там, где шейдер этого не подтверждает |
| Профили шейдеров | ваш JSON с правилами конвертации; матчится раньше поставляемых по умолчанию |
| Язык | EN / RU |

## Как читать отчёт

| Раздел | О чём говорит |
| --- | --- |
| `confidence: full` | шейдер разобран целиком: имя, свойства, дефолты, атрибуты |
| `material_only` | шейдер не найден — проверьте, добавлена ли его папка |
| `unmapped` | свойство прочитано, но эквивалента в Principled нет; кандидат на профиль |
| `stale` | свойство осталось от прежнего шейдера, Unity его тоже не рендерит |
| «с ненайденными текстурами» | текстура нужна шейдеру, но её папка не добавлена в источники |

## Частые вопросы

**Параметры материала серые, ничего не правится.** Способ импорта — `Связь с
библиотекой`. Либо переключите настройку на `Копия в файле` и перетащите заново,
либо сделайте редактируемую копию (`Ctrl+Shift+M`).

**`Ctrl+Z` не отменяет перетаскивание.** То же самое: при связи Blender не
выгружает библиотечные данные при откате. С режимом `Копия в файле` откат
полный.

**Материал должен быть цветным, а он серый.** Две причины, обе видны в отчёте:
не найден шейдер (`material_only`) — добавьте его папку; или шейдер найден, но не
подтверждает, что цвет умножается на альбедо. Доказательством считаются атрибут
`[MainColor]`, заголовок `[Header(Albedo)]` над свойством или профиль; на крайний
случай есть общий выключатель «Применять цветовой тинт всегда».

**Часть текстур не найдена.** Добавьте их папку источником «Текстуры и шейдеры».
Аддон принципиально не ищет по всему проекту — иначе неясно, что именно он
прочитал.

**Многослойные материалы выглядят как один слой.** Блендинг четырёх слоёв по
вершинным цветам пока не воспроизводится: строится слой 1, остальные честно
перечислены в `unmapped`.

**Библиотеку можно перенести на другую машину?** Да, если проект Unity лежит по
тому же пути; иначе пути к текстурам придётся перепривязать.

---

## Что аддон не делает

- Не пишет в проект Unity и не требует там никаких скриптов.
- Не копирует текстуры: в библиотеке только пути на исходные файлы.
- Не удаляет материалы, пропавшие из Unity, — только сообщает о них.
- Не гарантирует попиксельного совпадения с рендером Unity: цель — визуально
  достоверный рабочий материал, истина остаётся в Unity.
