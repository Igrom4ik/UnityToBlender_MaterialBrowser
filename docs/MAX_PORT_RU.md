# Перенос в 3ds Max — план

Цель: второй фронтенд к тому же ядру. Из материалов Unity собирается библиотека
материалов 3ds Max, пригодная к назначению на объекты, — тем же конвейером,
которым сейчас собирается библиотека Blender.

Целевые версии: **3ds Max 2024–2026**, материал — **Physical Material**.
Раскладка: **один репозиторий, два фронтенда**.

---

## 1. Что уже готово и переносится без изменений

Замерено на текущем коде, а не предположено:

| | |
| --- | --- |
| Ядро `unity_pipeline_core/` | 12 файлов, 102 КБ, `bpy` не импортируется ни разу |
| Совместимость с Python | AST-скан не нашёл ни одной конструкции новее **3.7**: ни `match`, ни рантайм-`\|`, ни `dict[...]` вне аннотаций. Везде `from __future__ import annotations`, поэтому аннотации не вычисляются |
| Blender-надстройка | 9 файлов, 123 КБ — это и есть объём работы, который надо написать заново для Max |

Python в Max 2024–2026 — 3.9 и новее, то есть **фаза A переносится копированием**:

- парсер `.mat` и `.meta`, GUID-индекс;
- парсер шейдеров (`shaderlab`, `shadergraph`, `builtin`, `material_only`) и слой
  `effective` со `stale`/`hidden`;
- side-car JSON, индекс, отчёт покрытия;
- профили шейдеров (`default_profiles.json`, `scale_from`, роли текстур);
- диффер: `.mat`, штампы текстур, штамп шейдера, версия парсера;
- `ConversionPlan` — уже renderer-agnostic: роли текстур, каналы, упаковка,
  metallic/roughness, тинт, tiling. Он и есть контракт между ядром и фронтендом.

Пять инвариантов действуют без изменений. Unity по-прежнему только читается,
текстуры не копируются, библиотека — локальный производный артефакт, всё
локально, читаются только явно выбранные папки.

## 2. Что придётся написать заново

| Модуль Blender | Что делает | Аналог в Max |
| --- | --- | --- |
| `node_builder.py` | дерево нод из `ConversionPlan` | построение Physical Material: параметры + Bitmap-текстуры, распаковка `_NMG`, инверсия smoothness |
| `library_build.py` | `.blend`, каталоги, разметка ассетов | `.mat`-библиотеки по каталогам Unity |
| `preview.py` | рендер иконок 128×128 | вероятно не нужен: Material/Map Browser рисует превью сам — **проверить** |
| `ui.py`, `properties.py`, `operators.py` | панель, настройки, операторы | PySide2/6 диалог + пункт меню из startup-скрипта |
| `registration.py` | регистрация классов | не нужна |
| `localization.py` | EN/RU строки | переносится как есть |

## 3. Маппинг `ConversionPlan` → Physical Material

Черновик, который проверяется на реальных материалах в M2:

| Из плана | Physical Material |
| --- | --- |
| `base_color`, текстура `BASE_COLOR` | `base_color` / `base_color_map` |
| `metallic`, `METALLIC_GLOSS` | `metalness` / `metalness_map` |
| `roughness` (уже `1 − smoothness`) | `roughness` / `roughness_map` |
| `NORMAL`, `normal_strength` | `bump_map` = Normal Bump, `bump_map_amt` |
| `OCCLUSION`, `occlusion_strength` | микс в `base_color_map` (у Physical нет AO-слота) |
| `EMISSION`, `emission_color` | `emission` / `emit_color` / `emission_map` |
| `alpha`, `alpha_cutoff`, `blend_mode` | `transparency` / `cutout_map` |
| `tint_color`, `tint_factor` | Color Correction поверх base color map |
| `scale` / `offset` текстуры | координаты Bitmap: `coords.U_Tiling`, `V_Tiling`, `U_Offset`, `V_Offset` |
| `colorspace` (`Non-Color`) | `gamma` = 1.0 у Bitmap вместо sRGB |

Упаковка `_NMG` (RG нормаль, B metallic, A gloss) сейчас разбирается нодами
Blender; в Max это цепочка Composite/Color Correction или `RGB Channel` —
единственный кусок, который придётся именно **проектировать**, а не переносить.

## 4. Чем в Max является «библиотека»

Прямого аналога Asset Browser с каталогами нет. Решение по умолчанию: **одна
`.mat`-библиотека на каталог Unity**, зеркалящая структуру папок — их видно в
Material/Map Browser и они переносятся между сценами. Альтернатива (`.max` на
материал + Asset Tracking) даёт превью и drag & drop, но плодит тысячи файлов и
требует открытой сцены.

Проверить до реализации (M1): пишет ли pymxs `.mat` в фоновом режиме
(`3dsmaxbatch`), не открывая GUI. Если нет — сборка станет операцией внутри
сессии Max, как сейчас фаза B в Blender.

## 5. Раскладка репозитория

```text
unity_pipeline_core/        ← общее ядро, единственный источник правды
unity_material_browser/     ← фронтенд Blender (выпущен, 0.12.1)
unity_material_max/         ← фронтенд 3ds Max (новый)
tools/build_extension.py    ← zip расширения Blender
tools/build_max_plugin.py   ← пакет для Max (M1)
tests/                      ← тесты ядра; свои сквозные у каждого фронтенда
docs/
```

Ядро вендорится в каждый фронтенд на этапе сборки — механика уже есть в
`build_extension.py` и повторяется для Max.

**Теги релизов получают префикс продукта:** `blender-v0.13.0`, `max-v0.1.0`.
Workflow триггерится по обоим префиксам и собирает соответствующий пакет. Это
единственная правка в CI, и её делаем в тот момент, когда Max-плагин впервые
собирается, — до тех пор `v*` продолжает работать как сейчас.

## 6. Этапы

**M0 — каркас.** Ветка `max-port`, каталог `unity_material_max/`, вендоринг
ядра, запуск `import unity_pipeline_core` внутри Max и чтение существующего
JSON-дерева. Проверка: в листенере Max печатается число материалов из
`_ump_index.json`, собранного Blender-версией. Это доказывает, что фаза A
работает, ещё до единой строчки построения материалов.

**M1 — библиотека.** Запись `.mat` из плана: один материал, потом каталог.
Проверка: файл открывается в Material/Map Browser, материал назначается на
объект, текстуры находятся по путям в `Assets/`.

**M2 — конвертация.** Полный маппинг из раздела 3, распаковка `_NMG`, инверсия
smoothness, tiling. Проверка: те же 24 материала `Bricks` и 11 `Blends`, на
которых проверялась Blender-версия, — сравнение бок о бок со скриншотом из
Unity.

**M3 — UI.** Диалог PySide: папки-источники, папка библиотеки, кнопки
«Извлечь» / «Собрать» / «Проверить обновления», отчёт. Настройки живут в
`%LOCALAPPDATA%`, а не в сцене.

**M4 — установка и релиз.** `.mzp` или папка в `scripts/startup`, пункт меню,
`tools/build_max_plugin.py`, тег `max-v0.1.0` и сборка в CI.

## 7. Риски

| Риск | Что делаем |
| --- | --- |
| CI без 3ds Max (нужна лицензия) | ядро тестируется в CI как сейчас; Max-часть — локальным сквозным скриптом по образцу `tests/blender_material_ops.py` |
| `.tif` — 85% текстур проекта | проверить чтение штатным Bitmap на M1; если тормозит, конвертация в кэш вне библиотеки (инвариант 2 запрещает класть её внутрь) |
| Ориентация зелёного канала нормали | сверить на одной карте в M2 и зафиксировать флаг, а не подбирать на глаз |
| Расхождение Physical и Principled | цель прежняя — визуально достоверно, истина в Unity; расхождения идут в отчёт, а не подгоняются |
| Ядро начнёт обрастать «максовыми» ветками | ядро не импортирует ни `bpy`, ни `pymxs` — это правило проверяется тестом, как сейчас |
