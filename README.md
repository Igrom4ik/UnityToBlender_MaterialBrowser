# Unity Material Browser 0.12.0

Аддон Blender 5.2, который превращает материалы Unity в библиотеку ассетов
Blender: материалы появляются в Asset Browser с каталогами по структуре папок
Unity, назначаются перетаскиванием на объект и обновляются при изменениях в
Unity.

- Как пользоваться: [`docs/USAGE_RU.md`](docs/USAGE_RU.md)
- Проект системы и принятые решения: [`docs/MATERIAL_BROWSER_RU.md`](docs/MATERIAL_BROWSER_RU.md)

## Правила, которые аддон не нарушает

1. **Unity только читается.** В проект Unity не пишется ни один файл; никаких
   скриптов и хуков на стороне Unity не требуется.
2. **Текстуры не копируются.** В библиотеке хранятся только пути на исходные
   файлы в `Assets/`.
3. **Библиотека не для git.** Это локальный производный артефакт; в её папку
   автоматически кладётся `.gitignore`.
4. **Система локальная.** Никаких серверов и сетевых сервисов.
5. **Читаются только выбранные папки.** Материалы, шейдеры и текстуры ищутся
   в добавленных вами папках и их подпапках — ни `Assets/` целиком, ни проект
   Unity не обходятся. Ссылка на файл вне этих папок остаётся неразрешённой и
   попадает в отчёт.

## Как это работает

```text
Фаза A (Extract)   Unity .mat + .shader + .meta  ->  materials/**/<имя>.json
Фаза B (Build)     <имя>.json                    ->  <имя>.blend + превью PNG
```

JSON — источник истины, `.blend` — производное. Поэтому пересборка после правки
правил конвертации не требует доступа к проекту Unity.

Значения, которых нет в `.mat`, берутся из блока `Properties` шейдера, а
свойства, которых в шейдере нет, отбрасываются как остатки прежнего шейдера и
попадают в список `stale`. Без этой сверки конвертер подключал бы текстуры,
которые Unity не рендерит.

## Установка

1. Соберите архив:

```bash
python tools/build_extension.py --output-dir dist
```

2. В Blender: `Edit > Preferences > Extensions > Install from Disk`, выберите
   `dist/unity_material_browser-0.12.0.zip`.
3. Откройте `3D View > N-панель > Unity Materials`.

## Порядок работы

1. **Библиотека.** Добавьте папки Unity: тип `Материалы` — где лежат `.mat`,
   тип `Текстуры и шейдеры` — папки, нужные для разрешения GUID. Если не указать
   папку текстур, пути к картам останутся неразрешёнными — это будет видно в
   отчёте.
2. Укажите папку библиотеки. Держите её вне проекта Unity и вне git.
3. **Сборка.** `Извлечь из Unity`, затем `Собрать библиотеку`.
4. Нажмите `Зарегистрировать в Asset Browser` — путь добавится в
   `Preferences > File Paths > Asset Libraries`.
5. Откройте Asset Browser и перетащите материал на объект. По умолчанию материал
   приходит копией в файл: его можно править, а `Ctrl+Z` отменяет перетаскивание
   полностью. Обновление из библиотеки — кнопка `Обновить материалы в этом
   файле`. В настройках можно переключить на `Связь с библиотекой`: пересборка
   тогда доходит до всех сцен сама, но параметры становятся серыми, а undo
   оставляет связь в файле.
6. `Ctrl+Shift+M` в 3D-виде открывает пай-меню материала: параметры,
   `Создать редактируемую копию` (копия с новым именем — так правка гарантированно
   не уедет в Unity при экспорте FBX), `Сбросить из Unity`, `Открыть Asset
   Browser`. Оператор копии есть и в меню-шестерёнке вкладки материала.
7. **Обновление.** `Проверить обновления` показывает новые, изменённые и
   пропавшие материалы; `Собрать только изменённые` перестраивает нужное.
   Изменением считается не только правка `.mat` и текстур, но и правка `.shader`
   и поднятая версия парсера — иначе улучшение конвертера не доходило бы до
   библиотеки. Пропавшие в Unity материалы остаются в библиотеке и не удаляются.

## Параметры сборки

| Параметр | Смысл |
| --- | --- |
| `Один файл на папку` | меньше файлов, быстрое сканирование библиотеки; пересборка одного материала переписывает всю папку |
| `Один файл на материал` | пересборка затрагивает один небольшой файл; создаются тысячи файлов |
| `Создавать превью` | рендер иконок 128×128 в отдельной сцене; PNG сохраняется рядом с материалом и переиспользуется при пересборке |
| `Профили шейдеров` | необязательный JSON с вашими правилами; он матчится раньше поставляемых `unity_pipeline_core/default_profiles.json`, а всё остальное решают эвристики по интерфейсу шейдера |
| `Перетащенный материал` | `Копия в файле` — правится и откатывается по `Ctrl+Z`; `Связь с библиотекой` — только чтение, зато пересборка доходит сама |

## Поддержка шейдеров

| Формат | Что читается |
| --- | --- |
| `.shader` (ShaderLab) | имя, свойства, значения по умолчанию, атрибуты, `#pragma surface` — покрывает и ручные HLSL/CG, и сгенерированные Amplify |
| `.shadergraph` | свойства графа и их reference-имена |
| встроенные шейдеры Unity | справочник `builtin_shaders.json`, сопоставление по `fileID` |
| шейдер не найден | режим `material_only`: конвертация по данным одного `.mat`, статус в отчёте |

Атрибуты дают правила без ручной настройки: `[HideInInspector]` отсеивает
служебные свойства, `[Normal]` определяет карту нормалей независимо от имени,
`[NoScaleOffset]` отключает tiling.

## Каналы и упаковка текстур

Unity хранит **smoothness**, Blender — **roughness**, поэтому значение всегда
инвертируется: `roughness = 1 − smoothness`. `_GlossMapScale` — множитель карты,
а не сама гладкость, и применяется до инверсии. `_SmoothnessTextureChannel: 1`
переносит гладкость в альфу albedo, и тогда эта альфа не используется как
прозрачность.

Постфикс имени файла распознаётся и подключается по назначению — он надёжнее
имени слота, потому что кастомный шейдер может подавать упакованную карту через
слот вроде `_BumpMap` или `_Normals`:

| Постфикс | Каналы | Куда идёт |
| --- | --- | --- |
| `_BC` | RGB base color | Base Color |
| `_BCA` | RGB base color, A прозрачность | Base Color + Alpha |
| `_BCH` | RGB base color, A высота | Base Color; альфа не идёт в прозрачность |
| `_NMG` | RG нормаль, B metallic, A gloss | распаковка: Metallic, Roughness и Normal |
| `_N` | нормаль | Normal Map |
| `_AO` | окклюзия | микс в Base Color |

Для `_NMG` синий канал нормали отсутствует и восстанавливается как
`sqrt(1 − x² − y²)`: оставить его единицей значило бы сгладить рельеф и исказить
освещение.

## Что сознательно не делается автоматически

- Цветовой оттенок (`_Color`) не умножается на базовую текстуру, если шейдер
  кастомный и намерение не доказано: доказательством считается атрибут
  `[MainColor]`, заголовок `[Header(Albedo)]` над свойством или профиль. Иначе
  свойство попадает в отчёт `unmapped`, а не искажает вид библиотеки. Общий
  выключатель «Применять цветовой тинт всегда» есть в настройках.
- Detail- и secondary-карты не подключаются: у них нет эквивалента в Principled.
- Материалы, пропавшие из Unity, не удаляются.

## Разработка

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

```bash
python -m compileall -q unity_pipeline_core unity_material_browser tools
```

Сквозная проверка в Blender:

```bash
blender --background --factory-startup --python tests/blender_smoke.py -- --zip dist/unity_material_browser-0.12.0.zip --materials <папка .mat> --assets <папка текстур> --assets <папка шейдеров> --library <папка библиотеки>
```

Операторы, которые проверяются только внутри Blender — способ импорта библиотеки,
редактируемая копия, поведение undo после перетаскивания:

```bash
blender --background --factory-startup --python tests/blender_material_ops.py -- --zip dist/unity_material_browser-0.12.0.zip --library <папка собранной библиотеки>
```

Ядро (`unity_pipeline_core/`) не импортирует `bpy` и тестируется без Blender;
сборщик копирует его в `unity_material_browser/core/` при упаковке.
